# The handshake program's Core, as Lean

These modules define `LinkedCore.file`: the elaborated Core of the
handshake program, as the Cerberus-Lean evaluator produces it from the C
sources. Its `main` is the test function in `../scenario/handshake.c`. Only
procedures reachable from `main` are kept.

- `WireGuard/<File>.lean` has one module per C file under
  `linux/drivers/net/wireguard/` whose functions the program uses
  (`WireGuard/Noise.lean` for `noise.c`, `WireGuard/NoiseH.lean` for
  `noise.h`). It holds one definition per C function, named as in C, in
  source order. Each doc comment quotes the function's C declaration and
  gives its `file:line`.
- `Support/Part01.lean` … `Part10.lean` define, in namespace `Support`,
  every other procedure the program uses: Linux library code, the
  execution environment and the Cerberus runtime library. They have C names
  and no source positions. The procedures are split over several files only
  to bound the memory needed to elaborate each one.
- `Program/Types.lean` names the C types that occur often (for example
  `Ty.struct_blake2s_ctx`). `Program/Helpers.lean` defines the short
  notation the definitions use: `c! "name" n` and `addr! "name" n` for
  symbols, `a! n` for unnamed ones, and `rg! «noise.c» l c l' c'` for
  source regions.
- `Program.lean` defines `LinkedCore.file`: the tags, the globals and the
  procedure maps, which refer to the definitions above.

Source locations are kept for `linux/drivers/net/wireguard/` and are
otherwise the unknown location.

`LinkedRun.lean` is the runner. `linked-run` executes `LinkedCore.file`
exactly as `cerberus-lean --batch --first --switches
PNVI_ae_udi,permissive_pointer_arith` executes the C input, and prints the
evaluator's verdict.

## Build

The evaluator is a Lake dependency, pinned by commit in `lakefile.toml`.
Its Lean sources are generated by its own build, which needs OCaml 5.4.0,
Dune and Lem on `PATH`; see `../RUNNING.md` for the exact versions.

    lake update
    (cd .lake/packages/CerberusLean && make lean-prelude-src && make lean-native-obj)
    LEAN_NUM_THREADS=2 lake build

Elaborating one of these modules takes up to about 5 GB of memory.
`LEAN_NUM_THREADS=2` limits the build to two modules at a time, which fits
in 16 GB. Without it, Lake elaborates as many modules at once as there are
cores.

## Run

    LEAN_ABORT_ON_PANIC=1 .lake/build/bin/linked-run

It prints one line, the verdict: `Defined {value: "Specified(0)", stdout:
"…", stderr: "", blocked: "false"}`. The default fuel is 2e12; set it with
`--fuel N`.

## Checks

    LEAN_ABORT_ON_PANIC=1 .lake/build/bin/linked-run --check

compares the MD5 of `LinkedCore.file`'s canonical text with `coreDigest`,
recorded when the modules were generated from the elaborated C. Equal
digests mean the definitions reassemble to the elaborated Core.

    LEAN_ABORT_ON_PANIC=1 .lake/build/bin/linked-run --roundtrip . ..

renders `LinkedCore.file` again, quoting the C declarations from the files
under `..`, and checks that it reproduces these modules byte for byte.
